# Deterministic scoring

`scoreAssessment` is a pure function over authenticated action context, retained receiver evidence, a trusted reputation snapshot, current policy, this agent's reconciled history and an injected clock. It does not call a model, execute evidence instructions, or fetch URLs.

The prototype indicator starts at 40. C’s trusted `independent_activity_credit` reduces it by at most 15; only labelled fixtures may fall back to their known-independent counterparty count. Live indexed activity earns no independence credit until C supplies that validated result; finalized successful agent interactions reduce it by two each, capped at 10. Unknown age, age below seven days, or fewer than three observed successes contributes one shared 15-point uncertainty cap. A recent deployment adds 20. Combined manipulation uses the maximum of provider/reputation feature values, capped at 30, and suppresses activity credit. Evidence-backed unresolved reports add at most 10. Scores clamp to 0–100. Below 30 can allow, 30 or more warns. The score is not a fraud probability.

Only an authenticated reviewed active entry matching network, account and optional code scope produces `block`; positive history cannot override it. A changed previously approved code identity forces `warn` regardless of score. Expired entries do not apply. Report count, common code or a common funder cannot independently create a block. C's trusted adapter is responsible for review authority, group diversity and common-faucet exemptions; the request cannot supply these claims.

Authorization requires a fresh policy and available reputation snapshot, receiver existence, and exactly one current `account_state` observation; calls also require `contract_code` and a supported code identity. Mandatory observations must carry matching network/source mode, real block height/hash and underlying block timestamp. Mandatory account/code facts must refer to the same concrete block. Both fetch and underlying timestamps must be within the policy maximum (at most 60 seconds); future timestamps fail. Missing mandatory inputs produce typed non-success responses with no permit. Optional historical incompleteness remains explicit.

Only one configured `memo-v1` target/method is supported. Raw arguments must be valid UTF-8 JSON with exactly the literal `memo` key and a bounded string value. Duplicate/escaped keys and unknown fields are rejected to avoid parser disagreement. Whitespace is permitted; the original bytes remain signed. Gas, deposits and total per-action value are bounded by the current policy with integer arithmetic. B's independent vault enforcement remains required.

Tests are in `packages/scoring/src/scoring.test.ts`; integration tests exercise the API's auth, durable permit and revalidation boundaries separately. The activity/dependence features are interfaces for C's forthcoming PR, not a replacement reputation implementation.
